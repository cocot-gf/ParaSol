# 教師なし学習 (正しくは自己教師あり学習)

このHow Toでは、教師なしの学習・推論の解説と、
応用アプリケーションとして、未知の異常検知として使える二値分類と、複数分類の2種類を紹介します。

## オートエンコーダを使った学習の手順
オートエンコーダとは、AIに学習させた入力データを推論結果として複製して得られるようにする学習方法です。
つまり入力データをそのまま教師データとすれば、オートエンコーダとして動作する教師あり学習です。

学習の手順は以下の通りです。  

    学習クリア  
    
    <学習回数ループ>  
       学習 x[inputSize], t[inputSize]  tデータはxデータと同一
    <ループ終了>  

* インスタンス初期化後の初めての学習前には、必ず学習クリアコマンドを実行してください。
* ParaSolの学習コマンドには教師データtの転送を省略し、内部でt=xとして流用するオートエンコーダ向けのコマンド StartTrain・StartTrain_X があります。
* 学習用の入力データは連続したデータでも、まったく関連性のないデータでも構いません。
* 学習データの性質や傾向によっては、正規化・標準化などの事前処理を入れたほうが学習精度が向上する場合があります。
* 通常、学習は一発のコマンドでは完了せず、数回学習させて学習が収束するのを待ちます。
  複数のデータを学習させるときは、AAAAABBBBBのように同じデータを連続させるより、
  ABABABABABと交互に学習させた方が両方がまんべんなく学習できるようです(忘却制御)。
* 学習が収束したかどうかを確認するには学習・推論+Loss取得を交互に実行し、Lossが低く落ち着いてくれば学習完了の目安です。
* しつこく学習を繰り返すと発散という状態になり、Lossが急に跳ね上がったり、推論出力Yに異常な結果が現れます。
  発散の状態になると学習をクリアしない限り収束に向かわないことが多いです。

## 推論の手順
推論は、学習した重みに沿って、推論入力に与えたデータから妥当と思われるデータを導く動作です。

ハッシュ変数のKey/Valueペアようなものをイメージすれば良いですが、
変数のように可逆データとして学習データが出てくるわけではなく、
重みを使って再生成しているのが処理の実態ですので、学習データと一致するデータが出てくることはまずありません。

推論の手順は以下の通りです。

    <推論回数ループ>  
        推論 x[inputSize], t[inputSize]  
        Loss取得 (任意)  
        推論出力y取得 (任意)  
    <ループ終了>  

* オートエンコーダで似たようなデータばかりを学習させた場合、推論入力に何を入れてもほとんど同じ推論出力しか得られません。
* 推論引数のtは、推論出力yとtを比較して損失Lossの値を計算するための比較データです。
* Lossは推論出力とtが一致していれば0となります。
この仕組みを利用して、学習データと推論結果がどれくらい一致しているかを比較できます。
* 推論出力Yも取得できるので他の処理(分類など)に利用できます。

# 応用アプリケーション
## 未知の異常検知・二値分類
機械の稼働状態を監視する場合、稀にしか起きない「故障の状態」を学習させるのは難しいものです。

代わりに正常な状態だけを学習させておき、稼働状況を推論で監視させると、正常状態からの外れ度合いから故障の兆候を検出できます。
巷にあるSolist-AIを使った異常検知システムは、たいていこの仕組みを利用しています。

異常の検出には人間の手で設定した何らかの閾値を設けなければいけません。これが二値分類である所以です。
閾値を使って正常か否かだけしか判別できないため、異常の内容を分類することはできません。


## 複数の分類
オートエンコーダで学習したものは二値分類になるので、多種の分類はひと手間かかります。

分類させる学習データを分類データベースDBとして保持しておき、推論コマンドには

    推論 x, DB1 ・ Loss1 取得  
    推論 x, DB2 ・ Loss2 取得  
    推論 x, DB3 ・ Loss3 取得  
    ...  
とLossの外れ度を総当たりで比較していきます。正直、ただの比較なのに推論にかかる時間が無駄です。  

もしくは、外部CPUが高速な場合は自前でMSEやMAEの比較ルーチンを作り、

    推論 x, x ・ Y取得  2つ目のxはダミーデータの扱い
    外部CPUで Y と DB1 を比較
    外部CPUで Y と DB2 を比較
    外部CPUで Y と DB3 を比較
    ...  
のように外部CPUでLossを計算してもよいでしょう。

Lossが一番小さいものが「該当の分類DBのデータに一番似ている」という判断材料になります。

教師あり学習の推論出力Yで直接分類するよりも柔軟な比較・類似した分類ができるので、
比較するデータによってはうまく分類できることが多いです。

デメリットとしては当然のことながら、分類DBが必要になることです。
果たしてこれがAIの分類処理と言えるかと疑問に思われるでしょう。損失関数を使った単なる比較分類なのですから。
